Date: 2026-05-07  
Epic revue: Epic 1 - Fondation salon, legal, UX de base

## 1) Revue Epic 1

### Resultat global

- Stories terminees: `1-1` a `1-9` (100%).
- Qualite technique stable sur le socle: lint/typecheck/tests verts a chaque livraison one-shot.
- Valeur produit livree: flux creer/rejoindre, legal, a propos, persistance V1 explicitee, warning navigateur, limites FR27, garde-fou DS.

### Ce qui a bien fonctionne

- Boucle one-shot efficace: implementer -> verifier -> reviewer -> patcher dans la meme passe.
- Discipline de contrats explicites (API + UI + messages) qui a limite les regressions.
- Couverture tests progressive sur les chemins critiques (join, erreurs, focus, capacite).
- Harmonisation design system en continu (tokens + focus + erreurs + warning surfaces).

### Ce qui a coince / points d'attention systeme

- Derives mineures recurrentes "valeur en dur" detectees par review (ex: longueurs/chiffres dans UI/tests).
- Fragilites initiales de portabilite environnements (Python tooling root, comportements shell) qui ont demande des ajustements.
- Risque de divergence entre constantes backend et frontend si non centralisees par contrat/versionning.
- Testabilite accessibilite encore basique (focus present, mais couverture a etendre sur parcours complets clavier).

### Lecons apprises

1. Les constantes produit critiques (format code, capacite, messages limites) doivent etre derivees, pas dupliquees.
2. Les revues multi-couches trouvent rapidement des ecarts non fonctionnels (DS, a11y, robustesse) utiles avant dette.
3. La doc operationnelle (README + contrats) doit evoluer en meme temps que le code pour conserver la fiabilite de l'onboarding.

### Dette technique restante (non bloquante Epic 1)

- Stockage salle/session encore en memoire process (non distribue).
- Pas encore de couche de persistance durable ou synchronisation multi-instance.
- Observabilite et diagnostics encore minimaux.
