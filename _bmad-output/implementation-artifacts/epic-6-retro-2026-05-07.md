## 1) Revue Epic 6

### Resultat global

- Stories terminees: `6-1` et `6-2` (100%).
- **FR19 / NFR-I1:** canal assist **non bloquant** — endpoints `GET /ai/assist/status`, `POST /ai/assist/ping`, preference **session** (`sessionStorage`), pas de fetch automatique au montage web (evite les regressions Vitest et le bruit reseau).
- **NFR-S2:** cle **`MOUSQUETAIRE_AI_API_KEY`** uniquement cote API ; `.env.example` documentes ; aucun secret dans le bundle client.
- **FR20 / UX-DR13:** section **`#transparence-ia`** (perimetre, traitement, limitations), lien footer **Transparence IA**, lien contextuel **En savoir plus** avec `aria-label` dedie ; pastille **Assist IA** sur les retours diagnostic apres statut/ping.
- Qualite: **pytest** (`api/tests/test_ai_assist.py`), **Vitest** et **typecheck** au vert ; **README** sections 6.1 et 6.2.

### Ce qui a bien fonctionne

- **Separation nette** entre mutations de jeu (`/rooms/...`) et couche **assist** (`/ai/assist/*`) — pas d’entrelacement dans la boucle tour / grille.
- **Degradation explicite** en JSON (`ok`, `message_fr`, `latency_ms` nullable) plutot qu’erreurs opaques pour le joueur.
- **Accessibilite:** deux liens vers la meme ancre sans collision de nom accessible (footer vs panneau assist).
- **Journalisation:** exclusion du GET `/ai/assist/status` des logs `http_request` support, alignee sur les autres sondes legeres.

### Ce qui a coince / points d’attention systeme

- **`App.tsx` continue de grossir** — l’engagement recurrent (Epic 5 retro) d’extraire le shell / legal / assist n’est toujours pas traité ; tout nouvel encart legal ou technique accentue la dette de lisibilite.
- **Fonctions IA « reelles »** (appel fournisseur, suggestions en partie) **hors livraison** de 6.1/6.2 : l’epic couvre **cadrage, toggle, transparence et diagnostic** ; la promesse produit « IA qui aide a jouer » reste a definir dans une slice ulterieure pour eviter la confusion utilisateur.
- **Couverture:** pas encore de test E2E dedie au clic statut/ping assist ; la couche reste fine mais gagnerait un scenario Vitest d’integration minimal si le panneau grossit.

### Lecons apprises

1. Pour les integrations sensibles (secrets, tiers), **livrer d’abord** statut + transparence + opt-in **sans** hook gameplay reduit le risque de blocage multijoueur.
2. **Ne pas fetch au montage** quand la base de tests mock `fetch` par URL — privilegier **actions utilisateur** ou un hook conditionnel pour garder les tests existants stables.
3. Les textes **transparence** en FR sobre et juridiquement prudents s’alignent bien sur les encarts CGU / risques deja presents — **garder le meme registre** pour les evolutions Epic suivants.

### Dette technique restante (non bloquante cloture Epic 6)

- Brancher un **fournisseur LLM** reel derriere la cle serveur (timeouts, quotas, journalisation sans donnees personnelles inutiles).
- Extraire **LegalFooterBlock** / panneau assist depuis `App.tsx` si le produit ajoute routes ou modes.
- Preciser produit + UX quand une **vraie suggestion IA** apparaitra en jeu (indicateur discret deja amorce pour le canal diagnostic uniquement).
