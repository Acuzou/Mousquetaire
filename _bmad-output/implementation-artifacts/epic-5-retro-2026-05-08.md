# Retrospective Epic 5 - Mousquetaire

Date: 2026-05-08  
Epic revue: Epic 5 - Solo pedagogique (FR17, FR18)

## 1) Revue Epic 5

### Resultat global

- Stories terminees: `5-1` et `5-2` (100%).
- **FR17:** parcours **sans code de salle** accessible depuis les onglets Multijoueur / Apprentissage solo dans `App.tsx`, module **`web/src/features/solo/SoloLearning.tsx`** avec etapes textuelles puis **atelier grille** réutilisant les classes **`word-grid` / `word-card`** et le même rituel selection → **Reveler la selection** → toast (alignement UX-DR10 avec le multi).
- **FR18:** panneau de **fin nominale** (felicitations, recap a puces, retour multijoueur, recommencer) ; **progression session** via **`sessionStorage`** (`mousquetaire_solo_v1`) avec **Reprendre / Recommencer** documentes lorsque le joueur quitte avant la fin ; garde-fou pour ne pas **ecraser** une sauvegarde tant que le choix de reprise n’est pas resolu.
- Qualite: **Vitest** et **typecheck** au vert ; **README** mis a jour (sections 5.1 et 5.2).

### Ce qui a bien fonctionne

- **Isolation fonctionnelle** du solo dans `features/solo/` sans toucher au backend ni aux contrats multijoueur — réduit le risque de regression Epic 3–4.
- **Réemploi visuel** du multijoueur (memes tokens CSS, hint irreversible, structure grille) — peu de divergence UX pour un cout de maintenance limite.
- **Persistance locale minimale** adaptee au MVP : pas de compte, pas de serveur pedagogique, mais parcours **reprehensible** dans la session avec texte clair sur les limites (fermeture d’onglet).
- **Tests ciblés** sur le flux nominal, la reprise et les restaurations depuis l’ecran de fin.

### Ce qui a coince / points d'attention systeme

- **`App.tsx` reste le pivot** du mode multi vs solo : l’engagement Epic 4 de **decouper** le shell applicatif n’est pas réalisé ; tout nouvel onglet ou route continuera d’alourdir ce fichier si on n’extrait pas un **layout** ou des **routes**.
- **`sessionStorage`** : comportement correct pour une session d’onglet, mais **opaque pour l’utilisateur** jusqu’au panneau de reprise — prévoir des messages produit si la retention pedagogique devient un KPI.
- **Pas de socle partage « composant grille » extrait** : la grille solo duplique la structure JSX du multi par convention de classes, pas par composant commun — acceptable V1, fragile si la grille multijoueur évolue fortement.

### Lecons apprises

1. Les features **100 % client** profitent d’une **spec de persistence** explicite tot (cle JSON, champs `step` / `completedNominal`) pour éviter les effets de bord au montage (ex. ecrasement avant « Reprendre »).
2. **FR17 + FR18** peuvent tenir en **deux stories courtes** si le perimetre nominal reste volontairement reduit (pas de scoring serveur, pas de lecons adaptees).
3. Garder le **meme vocabulaire de boutons** (« Reveler la selection », irreversibilite) renforce la **transferabilite** solo → multi pour les nouveaux joueurs.

### Dette technique restante (non bloquante cloture Epic 5)

- Extraire un **composant grille / carte** partage entre solo et multijoueur si les deux divergent davantage.
- Router ou layout dedie (`/solo`) si le produit ajoute d’autres modes ou landing pages.
- Persistance cross-session (localStorage, compte) uniquement si le PRD elargit le solo hors MVP.
